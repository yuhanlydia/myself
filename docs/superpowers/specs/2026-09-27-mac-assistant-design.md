# Myself：Mac 主动记忆助手第一版设计

日期：2026-09-27  
状态：供用户审阅；尚未实现、安装或发布。  
目标平台：macOS。GitHub 用于源码、测试及后续安装包发布；实际活动采集和个人记忆处理在用户的 Mac 上运行。

## 1. 用户目标

用户希望助手从已授权的电脑活动中了解当前工作，减少手工登记任务和反复讨论日程的负担，在适当时机直接提出下一步行动。长期目标涉及工作、伴侣、家庭、朋友以及健康和仪容等多种生活角色。隐私是设计约束。

第一版聚焦一个可验证的场景：用户被打断后，助手能恢复项目上下文，并结合已有时间约束提出下一步。电脑活动只能覆盖数字生活的一部分，不能据此推断线下关系、身体状况或全部生活优先级。

## 2. 范围与路线选择

| 方案 | 能力与限制 | 决策 |
| --- | --- | --- |
| 仅浏览器扩展 | 容易接入授权网页；无法完整了解本地应用活动 | 后续作为内容输入模块 |
| Mac 客户端 | 可连接操作系统允许的应用活动与本地通知；需要本机安装和权限 | 第一版主体 |
| 屏幕截图或全局输入为主要来源 | 内容丰富，但噪声、敏感信息和误读成本高 | 不作为默认输入 |

拟采用原生 Mac 菜单栏应用与本地存储。Swift/SwiftUI 是实现候选，具体版本、最低 macOS 版本及构建方式在实现计划阶段确定。浏览器扩展按选定网站逐步接入。

第一版包括：

- 用户主动开启的应用活动记录、暂停与恢复。
- 应用时间线和项目上下文，显示事实及其来源。
- 在明确授权的内容源中识别进展与未完成事项。
- 简单的可用时间和截止时间输入；外部日历连接留作独立模块。
- 带依据的下一步建议及“开始、稍后、已完成、判断错了”反馈。
- 查看、纠正、删除记忆的界面。

第一版不自动发送消息或修改第三方日程；不默认采集全局键盘文本、截图、剪贴板或私人通信；不自动启用登录启动。手表、手机、健康信号和真实人际互动模型作为后续独立阶段。

## 3. 感知和证据边界

活动层记录应用标识、观察时间、前台切换与活跃状态。窗口标题可能包含个人信息，作为单独可选项。内容层仅处理用户指定的来源；授权撤回后停止采集和使用对应来源。

网络请求不作为主要的任务理解依据：后台服务也会联网，HTTPS 内容不能直接从普通连接日志读出。

必须保留以下语义区别：

| 观察 | 能记录的事实 | 不应直接推断 |
| --- | --- | --- |
| 打开文档 | 文档在前台出现 | 已经阅读或理解 |
| 编辑并保存 | 获准读取的版本发生变化 | 内容已经完成或通过检查 |
| 文本出现在输入框 | 草稿存在 | 已发送、已承诺 |
| 发送状态可核实 | 内容已经发送 | 对方已经接受 |
| 电脑空闲 | 未观察到电脑交互 | 正在休息、运动或睡觉 |

没有内容访问权限时，助手只能恢复到应用或项目层面，不能声称知道某个段落的问题。不同网页和编辑器需要单独验证适配；不承诺通用读取所有应用。

## 4. 模块与数据流

1. **采集模块**：依据授权范围生成事件；不负责推断用户意图。
2. **事件整理模块**：去重、合并连续活动，区分观察时间和事件发生时间。
3. **记忆模块**：维护项目、进展、待办、承诺和偏好，并保留来源与状态。
4. **安排模块**：结合明确的时间约束提出一个下一步；未确认的推测不会直接变为已确认承诺。
5. **通知模块**：处理触发、延后、取消、去重和暂停；不依赖语言模型自行记住提醒时间。
6. **反馈模块**：将用户纠正写回记忆，更新任务与提醒状态。

语言模型负责语义理解和候选建议；确定性的程序负责权限检查、时间约束、取消状态和提醒去重。模型不可用时，时间线和明确设置的提醒仍应可用。

## 5. 记忆结构与最小存储

每条长期记忆至少包含：标识、所属项目或实体、内容、来源引用、观察时间、有效时间（如可知）、事实或推测标记、确认状态，以及相关权限范围。

任务另存状态：候选、已确认、进行中、完成、取消；候选事项必须有依据，用户未回复不视为确认。修改截止时间产生更新记录，使旧提醒失效。

原始活动事件采用有限保留期，建议默认七天并可调整；这是产品初始选择，不是研究证明的最优值。长期保留经过筛选的事件、必要证据和用户确认的信息。合并活动时不抹掉关键状态变化。

按键数、停留时长和窗口切换不直接等于效率、疲劳或人格。对偏好的推断保留样本依据，单次忽略通知不自动写成长期偏好。

压缩效果同时报告实际存储字节、模型调用量与决策错误，不能只以摘要长度或记忆条数宣称准确且低成本。

## 6. 隐私与权限设计

- 默认关闭采集，首次启用说明收集内容；菜单栏持续显示状态并提供暂停。
- 活动记录、窗口标题和内容读取分开控制；只在功能需要时申请相应系统权限。
- 原始内容默认在设备本地处理，不自动发送给云端模型。云端模式作为单独选择，并说明传输范围；摘要也视为可能敏感。
- 本地存储须具备静态加密方案，密钥由系统安全存储管理；具体实现需要在后续计划中验证，不能以普通数据库冒充已加密。
- 用户删除来源时，一并删除或重新计算依赖该来源的派生记忆、索引与待发提醒。多来源记忆需移除对应证据并重新判断是否仍受支持。
- 运行日志不写入正文、窗口标题、凭据或个人活动；开发和测试使用合成数据。
- GitHub 仓库只保存代码、文档及合成测试数据。运行时数据库、浏览记录、私人文档和密钥不进入版本控制。
- 页面文本是待处理内容，不是对助手的操作指令；从网页提取的文字不能自行获得工具权限。

## 7. 通知体验和异常处理

助手应给出一句具体建议、简短依据和可追溯入口。用户可以完成、延后或纠正，不要求每次进入聊天。

初始提醒策略采用保守默认：用户配置可提醒时段；主动建议至少间隔一小时、每天最多三次，可调整。这些数值是待验证的产品参数。用户明确创建的定时提醒单独管理；所有通知仍受暂停与取消控制。

- 权限被拒绝：显示当前可用能力，不循环弹出申请。
- 内容无法读取：保留活动事实，不补写虚构的项目进展。
- 模型无法判断：保留未知状态；高影响的时间冲突需要用户判断。
- 休眠、重启或时区变化：恢复时重新检查时间与任务状态，过时的建议不集中补发。
- 已完成或取消：对应待发提醒失效；同一事件不得重复通知。
- 本地数据写入失败：明确显示采集中断，不声称记录成功。

## 8. 验收场景

| 场景 | 通过条件 |
| --- | --- |
| 应用 A 切换到应用 B | 时间线正确且没有把后台进程当作前台工作 |
| 未授权的应用 | 不保存其标题或正文 |
| 只有应用活动，没有内容权限 | 建议明确停留在应用或项目层面 |
| 草稿包含“明天交稿” | 不自动生成已确认承诺 |
| 候选任务被用户纠正 | 后续建议采用纠正后的状态 |
| 任务改期、完成或取消 | 原触发不再发出提醒 |
| 删除一个来源 | 对应派生记录和待发提醒同步处理 |
| 休眠后恢复 | 不重复推送旧通知 |
| 模型离线 | 活动时间线与明确的提醒仍能工作 |
| 网页包含命令式文本 | 不触发越权工具调用或传输 |

实际使用评估关注：上下文恢复正确率、建议接受和纠正情况、错误提醒和漏提醒、每天手工操作次数、存储字节、运行开销及耗电。先报告样本和失败案例，不预设“记忆准确率 99%”等目标。

## 10. 已查阅的技术依据

- [Apple：控制输入监控权限](https://support.apple.com/guide/mac-help/control-access-to-input-monitoring-on-mac-mchl4cedafb6/mac)：输入监控属于独立权限范围。
- [Chrome：History API](https://developer.chrome.com/docs/extensions/reference/api/history)：浏览器访问历史接口。
- [Chrome：Content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)：获准网页中的内容访问机制。

以上来源支持局部能力，不构成完整助手已经实现或能够准确理解所有活动的证据。
